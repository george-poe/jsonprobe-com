A validator answers one question: does this parse as a single JSON value under RFC 8259. It says nothing about whether the content is what your API expected — that is schema validation, a separate check on a separate page.

      
Most validators in this category just relay the engine's message. Current V8 frequently reports something like Unexpected token '@', … is not valid JSON — a fragment of your text and no position. This page carries its own scanner for exactly that case, so you get a line and a column instead. Measured in Chrome 152 / Windows 11: a fault on line 2,419,794 of a 100 MB file is located in 1026 ms.

    
What this rejects

    
    

  • A byte-order mark before the first character. UTF-8 is required by the spec; a BOM is
not whitespace.
    • 

  • Comments — // and /* */. Legal in JSONC, which is what
tsconfig.json and VS Code settings use.
    • 

  • Trailing commas in an object or array.
    • 

  • Single-quoted strings, and keys without quotes.
    • 

  • NaN, Infinity, -Infinity,
undefined.
    • 

  • Raw control characters inside a string — a literal newline instead of
\n is the usual one.
    • 

  • Two values at the top level, including newline-delimited JSON (JSONL). Each line of a
JSONL file is valid; the file is not one JSON document.
    • 

  • An empty file, or whitespace only. There has to be a value.
    • 



And what it accepts that surprises people: duplicate keys.
{"a":1,"a":2} is valid JSON, and the last value wins. That is legal, not a
typo the validator will flag.

Frequently asked questions

    

      Is my JSON sent to a server?
      
No. There is no request in the code path — the text is parsed in a Web Worker inside the same tab. The Network panel stays empty while you validate.

    

    

      Can it check my JSON against a schema?
      
Not on this page. This one only answers "is it valid JSON". Schema validation is a separate tool and it is a draft-07 subset — see the JSON Schema validator page for what is and is not implemented.

    

    

      The error says a position like 148203. How do I find that?
      
Older engines printed a character offset; you were left counting. This page prints line and column, plus the surrounding text of that line, because it locates the fault itself rather than relaying the engine.

    

    

      Why does my .json file fail when the editor is happy with it?
      
The editor is probably reading JSONC or JSON5, which allow comments, trailing commas and unquoted keys. Those are not JSON. Either strip the extensions or keep the file named .jsonc.

    

    

      Is an empty file valid JSON?
      
No. A JSON text must contain exactly one value, and an empty file contains none. Neither is {} equivalent — if you want "nothing", write null.
