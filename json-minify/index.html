Minifying JSON deletes the whitespace between tokens and nothing else — not inside strings, not the key order, not the number values. That is checked rather than promised: for the payload measured above, the minified text is byte-identical to JSON.stringify(JSON.parse(pretty)). What can still change is the round trip itself, and the formatter page lists all six ways that happens.

      
The savings are real and bounded: 38.6% on the 2-space file measured above. If someone tells you minification will halve your payload, they are describing a file with unusually generous indentation.

Two honest qualifications. This sample is repetitive synthetic data, so its gzip ratio
is better than a real API response will be — and if the transport is HTTP/2 with
Content-Encoding: gzip or br, you are already paying for
compression, which is where the comparison applies.

    
Do not use minification as obfuscation

    
Minified JSON is one long line, which is inconvenient to read in a
text editor. It is not unreadable: any formatter turns it back, and a browser's dev tools
do it on click. If the content is sensitive, the answer is transport security and access
control, not whitespace.


The related trap runs the other way. Because a minified file is one line, tools that
report errors by line number become useless — "line 1, column 4,182,309" is technically
correct and practically painful. That is a reason to keep a pretty copy in version
control and minify only at build or deploy time.

    
Frequently asked questions

    

      Is minifying lossy?
      
Not for a valid JSON document: the same value comes out. It is lossy for comments and formatting, which is one more reason JSONC files should not be minified with a JSON tool — the comments are stripped by the parser, not preserved.

    

    

      How much smaller will my file get?
      
Around 40% for 2-space output, more for 4-space or tab-indented files, and nothing for a file that is already minified. The measured numbers are in the table above.

    

    

      Should I minify before or after compression?
      
Before, if you control the pipeline — it never hurts and it is cheap. But do not expect much: on the measured sample, gzip already takes the pretty file down by 99% and minifying first adds about 14%.

    

    

      Does minifying make it unreadable on purpose?
      
No, and do not count on it for secrecy. One click in any formatter, including this site, restores the indentation.
